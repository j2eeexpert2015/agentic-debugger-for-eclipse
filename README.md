# Agentic Debugger for Eclipse IDE

Debug **Java, JUnit 5, and Spring Boot** applications in Eclipse with **Claude Code** through the Model Context Protocol (MCP). The plugin uses Eclipse Java Debug Tools (JDT) for actual execution control; Claude selects and invokes MCP tools. Safety checks for session ownership, breakpoints and cleanup are implemented in Java, not left solely to prompt instructions.

**Evidence snapshot — 24 November 2026 (Windows, JDK 25.0.5, Eclipse 2026-09):** direct regression **23/23**, stop/output group **6/6**, abandoned-investigation group **5/5**, bridge fault injection **4/4**, unit tests **74/74** (JUnit 5, run by the Maven build), all with verified cleanup. Repeated Claude trials (3 per scenario, graded automatically from actual debugger results): **9/9 PASS with the skill, 17/18 without** (the one FAIL is a run where the Claude CLI ended early). Small samples on test fixtures: an indication, not a reliability statistic. Details per item: [Status and tracking](#status-and-tracking).

## Install and use

### Which Eclipse IDE?

Use **Eclipse IDE for Enterprise Java and Web Developers** (recommended for Spring Boot) or **Eclipse IDE for Java Developers**, with **Java/JDT debugging, JUnit and Maven/m2e** available. This is an **Eclipse IDE workbench plugin**, **not a standalone Eclipse RCP/RAP runtime application**. The Eclipse IDE for RCP and RAP Developers package has not been independently tested; it would need the Java tooling installed. **Spring Tools is optional**, and its specialized launch modes remain unverified.

Requirements: **JDK 21+** and authenticated Claude Code for Claude-driven use. Building from source requires Maven and Git. The 23-scenario direct regression ran on Windows, Eclipse 4.41 and JDK 25.0.5; no Python is required by the Java E2E framework.

### Install the plugin

1. Obtain an Eclipse **update-site ZIP** from [GitHub Releases](https://github.com/j2eeexpert2015/agentic-debugger-for-eclipse/releases) if available, or run `mvn clean package` and use the generated `eclipse-update-site/target/agentic-debugger-update-site-*.zip`. A GitHub source ZIP is **not** an installable Eclipse update site.
2. In Eclipse use **Help → Install New Software → Add → Archive**, select the update-site ZIP, install **Agentic Debugger for Eclipse IDE**, and restart.
3. Use **Window → Preferences → Agentic Debugger → Claude Code → Set up** to configure Claude Code. With Eclipse running and the project imported, check Claude's `/mcp` for `eclipse-debugger` and call `eclipse_ping` (expected `PONG`).

**Updating.** The product has three parts, and they are updated differently today:

| Part | Where it lives | How it is updated |
|---|---|---|
| Eclipse plugin (debugger bridge) | inside Eclipse | install the new version (Help → Install New Software, or `DevE2E deploy`), restart Eclipse |
| MCP server (`agentic-debugger-mcp.jar`, writes the reports) | `%USERPROFILE%\.eclipse-agentdebug\` | copied automatically from the plugin when Eclipse starts **normally** (not the test Eclipse of `DevE2E`); it cannot be replaced while a Claude session uses it, so close Claude sessions first, then start a **new** Claude session |
| Skill (`eclipse-debugger`) | `%USERPROFILE%\.claude\skills\eclipse-debugger\` | copied automatically from the plugin when Eclipse starts **normally** (OPEN-32), and from the repository before every Claude trial of `DevE2E`; a copy you edited yourself is kept, the new version is written next to it as `SKILL.md.new`; a copy made by hand before is kept as `SKILL.md.bak-<time>` |

Check: `%USERPROFILE%\.eclipse-agentdebug\agentic-debugger-mcp.jar` must have the time of the last normal Eclipse start after the update (an MCP server without reports is about 6 MB, with reports about 11 MB).

If something does not work, see [Troubleshooting](#troubleshooting) below.

**Registering by hand** (instead of the Preferences page, or for another MCP client). Any copy of the MCP server jar works: the one the plugin keeps in `%USERPROFILE%\.eclipse-agentdebug\agentic-debugger-mcp.jar` (refreshed at every normal Eclipse start, so it matches the plugin) or `mcp-server\target\agentic-debugger-mcp-1.0.0-SNAPSHOT.jar` from a build. For Claude Code:

```cmd
claude mcp add --transport stdio --scope user eclipse-debugger -- "C:\path\to\java.exe" -jar "%USERPROFILE%\.eclipse-agentdebug\agentic-debugger-mcp.jar"
```

Any other MCP client that starts stdio servers: command `java` (21 or newer), arguments `-jar <path to the jar>`, for example `{"mcpServers": {"eclipse-debugger": {"command": "C:\\path\\to\\java.exe", "args": ["-jar", "C:\\path\\to\\agentic-debugger-mcp.jar"]}}}`. The server connects to the Eclipse bridge on port **8765**; only when Eclipse uses another port, set `AGENTDEBUG_PORT` for the server (`claude mcp add --env AGENTDEBUG_PORT=<port> ...`, or an `"env"` entry). The earlier command-line setup utility (`installer`) was removed on 25 Nov 2026 (OPEN-38 step 5); if you used it, the Preferences page recognizes its registration and offers to move it to the plugin's jar.

### Ask Claude to investigate

Example symptom-only request: *“My orders API returns 120.00, but I expect 108.00. Find the cause. Do not modify source or unrelated running applications.”*

`NORMAL` investigations remove their **own** debugging resources when properly finished; `CONTROLLED` investigations may retain state. Neither authorizes changing user-owned breakpoints or unrelated launches. The [optional skill](skills/eclipse-debugger/SKILL.md) is not required for core MCP debugging.

**Debugging session report.** Every investigation is written as one HTML file: what was asked, the agent's conclusion, then every step (breakpoints, launches, stops with variables, HTTP requests, cleanup). It goes to the `debug-reports` folder of the Eclipse project the investigation launched, e.g. `<project>\debug-reports\OrdersApplication_2026-11-24_14-26-29.html`; with the skill, Claude tells you the full path at the end. Add `debug-reports/` to the project's `.gitignore` if you do not want to commit reports. Switch reports off with the environment variable `AGENTDEBUG_REPORT=off` for the MCP server, or send them to one folder with `AGENTDEBUG_REPORT_DIR` (a setting in Eclipse Preferences is planned). The path of each report is in the agent's answer and behind Open HTML Report in Agent Activity; `AGENTDEBUG_VERBOSE=1` also prints it in the MCP server's log.

### Use with GitHub Copilot (OPEN-23, checked with Copilot 0.22.0)

1. Install GitHub Copilot for Eclipse and sign in. Copilot 0.21.0 fails for Copilot Free with "No model configuration found" (Copilot issue #443); use 0.22.0 or later.
2. **Allow the server once.** The plugin offers **eclipse-debugger** to Copilot; Copilot lists it as *Denied* because the plugin is not signed. Window → Preferences → GitHub Copilot → Model Context Protocol (MCP) → **Edit MCP Servers from Plug-ins** → select *Agentic Debugger for Eclipse IDE* → **Approve**. The Tools list on the same page then shows the eclipse-debugger tools.
3. **Choose how Copilot debugs:**
   - **Agentic Debugger agent (the only mode that uses our tools):** Window → Preferences → Agentic Debugger → GitHub Copilot → Agentic Debugger agent → **Install** (for all workspaces), or for one project: right-click it → **Agentic Debugger → Add Agentic Debugger Agent for GitHub Copilot** (near the bottom of the menu). Use one of the two: Copilot lists every copy. It also installs the `eclipse-debugger` skill for Copilot (in `~/.copilot/skills/`, unless it is already in `~/.claude/skills/`). **Remove Agentic Debugger Agent for GitHub Copilot** in the same menu takes the agent out again (it asks first if you changed the file); the skill is removed on Window → Preferences → Agentic Debugger. It adds `.github/agents/agentic_debugger.agent.md`. In Copilot Chat, choose **Agentic Debugger** in the mode list (next to Ask, Agent, Plan): Copilot then debugs only with the eclipse-debugger tools, starting the program or test itself.
   - **Ask, Agent and Copilot's other agents do not get the eclipse-debugger tools** (OPEN-60, default): the plugin switches our tools off for Copilot's Agent mode (and so for every custom agent without its own tool list), and our agent declares its own list. Agent mode can also not hand the work to our agent. To let every mode use our tools, untick Preferences → Agentic Debugger → GitHub Copilot → *Only the Agentic Debugger agent, and without confirmations* (then Copilot asks before each tool).
4. Skills (Preferences → GitHub Copilot → Chat → Enable Skills): Copilot reads the `eclipse-debugger` skill from `~/.claude/skills/` or `~/.copilot/skills/`. Nothing is installed for Copilot unless you add the agent or install the skill on our preferences page.
5. **Nothing blocks a run in the Agentic Debugger agent** (OPEN-60): the plugin adds our server to Copilot's Tool Auto Approve list (only while the tools are limited to our agent), the agent has no terminal and no file-editing tools (so no "Allow" prompts), and expressions and tracepoints run without a question (Preferences → Agentic Debugger → *Ask before the agent runs code in the program* turns that question back on). The plugin changes only its own entries in Copilot's settings; changes apply when Eclipse restarts.
6. **Check setup:** Preferences → Agentic Debugger → **Check setup** shows what works (bridge, MCP server, Copilot approval, launcher, agent files, which modes get our tools, confirmations, Claude Code) and what to do; **Copy report** for an issue. A quiet check also runs 30 s after Eclipse starts, for the integrations in use; a problem shows as "check setup" in the status bar and in the Error Log (OPEN-61).

Without approving the server, Copilot never sees these tools and works as before with its own `java_debugger`. The plugin does not change your own launches, breakpoints or settings.

**FAQ**
- *"Unknown investigationId … Refused; nothing was changed" in the chat:* the agent sent an ID that does not match its investigation, usually a copying slip by the model. The debugger refuses on purpose, so an agent never controls a session that is not its own; the agent normally retries with the right ID.
- *eclipse-debugger shows as Denied again:* Copilot asks again whenever the command it runs changes. On Windows, since 26 Nov (OPEN-23 step e), the command is a launcher script that stays the same when Eclipse or its Java is updated; you approve once more after moving to this version, and again only if the plugin's setup changes (for example another bridge port). On Linux and macOS the command still names Eclipse's Java, so approve again after an Eclipse update (OPEN-54).
- *Copilot's MCP log shows `[error] [Server: github] ... missing required Authorization header` at start:* that is GitHub's own MCP server, which Copilot connects to by itself, not the Agentic Debugger; it changes to "Connection state: Running" a moment later. The eclipse-debugger server prints nothing during a normal start; with the environment variable `AGENTDEBUG_VERBOSE=1` it prints its startup and report lines for troubleshooting (Copilot shows them as [warning]).
- *The mode button is blank, or Agentic Debugger is missing from the mode list:* a GitHub Copilot issue (OPEN-51): open **Configure Agents...** in that list once and close it; Copilot then reloads its custom agents. Details: [docs/copilot-mode-list-bug.md](docs/copilot-mode-list-bug.md).
- *The model name in Agent details looks wrong:* it is what the agent says about itself (marked ◆); Eclipse cannot verify it.
- *The tool boxes for our agent on Copilot's Tools page:* our agent lists its tools itself (OPEN-60). If you click Apply there for the Agentic Debugger mode, Copilot rewrites the agent file; the plugin then treats it as your edit (its next version goes next to it as `.new`). Change our tools with our preference, not on that page.
- *Agent mode still used our tools:* restart Eclipse (the setting is applied when Copilot starts), then Preferences → Agentic Debugger → Check setup; send the report if it says our tools are still on for Agent mode.

After an Eclipse update with a new built-in Java, Copilot lists eclipse-debugger as *Denied* again (the command it runs changed): approve it again as in step 2. Copilot shows the server's status lines as "[warning]" in its log; that is normal (OPEN-44).

### Troubleshooting

| Problem | Check |
|---|---|
| `mvn` or `java` not recognized | Install the JDK (21+) and Maven; `java -version` and `mvn -version` must work in a new terminal |
| Plugin missing after installing | Help → About Eclipse IDE → Installation Details → Installed Software; restart Eclipse |
| Claude cannot reach Eclipse | Keep Eclipse running with the project imported; check `/mcp` for `eclipse-debugger` and call `eclipse_ping` (expected `PONG`); close other Eclipse instances that use the same bridge port |
| Old behaviour after an update | The MCP server jar is copied on a **normal** Eclipse start; close Claude sessions, start Eclipse normally, start a new Claude session (see Updating above) |
| JUnit test cannot be launched | JDT JUnit support present, the Maven project imported and built, the test method name exact |
| Breakpoint never stops | The line has code, the right application is launched, a condition is valid in that scope |
| Claude names the bug without debugger calls | A correct static diagnosis is not agentic debugging; ask explicitly to debug, and check the session report |
| Development test setup (`DevE2E`) | `java dev-e2e/DevE2E.java config` lists every setup problem with what to do |

To uninstall: Help → About Eclipse IDE → Installation Details → Installed Software → Uninstall. Remove the Claude Code
registration through Window → Preferences → Agentic Debugger → Claude Code; it never touches unrelated entries.

## Build and test commands

All commands run from the repository root. There are two kinds of tests, and they never mix:

| Kind | What it checks | Needs | Runs with |
|---|---|---|---|
| **Unit tests** (JUnit 5) | Logic that needs no Eclipse: bridge protocol, ownership and lease rules, output trimming, MCP timeouts, setup utility paths, Claude grader | JDK 21+, Maven | `mvn clean package`, automatically |

### Build and unit tests (no Eclipse needed)

```cmd
:: Build everything and run all unit tests; a failing unit test fails the build
mvn clean package

:: Build without running unit tests
mvn clean package -DskipTests

:: Unit tests of one module only, plus the modules it needs (-am), for example mcp-server, testing, report
mvn clean package -pl mcp-server -am
```

Use `package`, not `mvn test`: the plugin build copies the mcp-server jar, which exists only after `package`.

### Integration tests (dedicated test Eclipse)

The integration tests are JUnit 5 classes (one per product feature) that drive the installed plugin in a dedicated test Eclipse. One-time setup on each machine: create the untracked `dev-e2e/e2e.properties` from [the example](dev-e2e/e2e.properties.example), with a **dedicated Eclipse installation**, a **disposable workspace** and a **non-default bridge port**; `java dev-e2e/DevE2E.java config` checks it and explains each problem.

```cmd
:: 1. Prepare the test Eclipse (close it first for all/deploy): build + install + start, install + start, or start only
java dev-e2e/DevE2E.java all
java dev-e2e/DevE2E.java deploy
java dev-e2e/DevE2E.java start

:: 2. Run the tests: the regression suite (default, 27 tests); -Dfixture.post.approved=true allows the HTTP tests
mvn -pl testing verify -Pintegration-tests -Dfixture.post.approved=true

:: Another suite (FullSuite 43, ExtendedSuite 22), one class, or one test
mvn -pl testing verify -Pintegration-tests -Dit.test=FullSuite -Dfixture.post.approved=true
mvn -pl testing verify -Pintegration-tests -Dit.test=BreakpointTests
mvn -pl testing verify -Pintegration-tests -Dit.test=BreakpointTests#conditionalStopsOnlyOnMatch
```

Or right-click `RegressionSuite` or any test class in the IDE, Run As, JUnit Test.

```cmd
:: Rebuild the newest trial report from its recorded events (kept as *.events.jsonl by every trial with -Dclaude.report=true) and run

java dev-e2e/DevE2E.java report-replay
```

## Development workflow

Coding agents start with [AGENTS.md](AGENTS.md); everyone follows the [development workflow](docs/development-workflow.md) (with the architecture and source map).

Changes follow an **evidence-first, reviewable process**: reproduce and isolate the issue; prepare a minimal, reversible change; compile and test the affected scenario; run broader regression; independently review Claude MCP evidence when applicable; then update the tracking table and documentation. **Do not treat `REVIEW_REQUIRED` as a PASS or run paid Claude trials without approval.**
